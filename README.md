# ru-news-dashboard

Лента заголовков независимых и эмигрантских русскоязычных СМИ.
Форк `eu-news-dashboard`: та же архитектура (статика + serverless-функции Vercel),
переписанные источники и парсинг под кириллицу.

## Структура

```
index.html          вёрстка
app.js              фронтенд: фильтры, рендер, сводка
styles.css          стили (винная палитра)
middleware.js       Edge Middleware: проверка сессии на КАЖДОМ запросе
login.html          страница входа
lib/auth.js         PBKDF2, подпись сессий, куки
api/login.js        POST — проверка пары логин/пароль
api/logout.js       POST — сброс сессии
api/news.js         сбор новостей + кеш в памяти (5 мин)
api/claude.js       прокси к Anthropic API для сводки дня
api/health.js       health check
lib/sources.js      34 источника: URL, регулярки, RSS, политики дат
lib/fetch-news.js   парсер: RSS + HTML, извлечение дат, дедупликация
tools/verify-sources.mjs   проверка живости источников
tools/hash-password.mjs    генерация хеша пароля и секрета
```

## Аутентификация

Дашборд закрыт полностью: middleware проверяет сессию до того, как отдать
хоть что-нибудь, включая `/api/news`. Проверки на стороне фронтенда нет
намеренно — она бесполезна, `/api/news` дёргается напрямую в обход любой
JS-логики в браузере.

Настройка перед первым деплоем:

```bash
npm run hash-password
```

Скрипт спросит логин и пароль (ввод скрыт) и напечатает три переменные.
Занеси их в Vercel → Project → Settings → Environment Variables:

| Переменная | Что это |
|---|---|
| `AUTH_USERNAME` | логин |
| `AUTH_PASSWORD_HASH` | `pbkdf2$210000$<соль>$<хеш>` — сам пароль не хранится |
| `AUTH_SECRET` | 32 байта для подписи сессионных кук |
| `AUTH_SESSION_TTL` | необязательно, срок сессии в секундах (по умолчанию 14 дней) |

Пока переменные не заданы, middleware отвечает 503 всем без исключения —
чтобы не получилось «задеплоил и забыл настроить», оставив ленту открытой.

**Как это устроено.** Пароль хешируется PBKDF2-HMAC-SHA256, 210 000 итераций
(рекомендация OWASP), со случайной солью. Сравнение хешей и подписей идёт за
постоянное время, чтобы по задержке ответа нельзя было подбирать значение
посимвольно. При успешном входе ставится кука `HttpOnly; Secure; SameSite=Lax`
с HMAC-подписанным токеном — прочитать её из JS нельзя, подделать без
`AUTH_SECRET` тоже.

**Сменить пароль:** прогони `npm run hash-password` заново и обнови
`AUTH_PASSWORD_HASH`. **Выкинуть все активные сессии:** смени `AUTH_SECRET` —
все ранее выданные куки станут невалидны.

### Что здесь слабое

Троттлинг попыток входа (10 за 15 минут) живёт в памяти инстанса. Vercel
поднимает инстансы независимо, так что перебор через них размазывается.
Для одного пользователя с длинным паролем этого хватает, но если нужен
настоящий лимит — заведи Upstash Redis или Vercel KV и перенеси счётчик
из `api/login.js` туда.

Второго фактора нет. Если лента станет чем-то большим, чем личный дашборд,
проще подключить готовый провайдер (Auth0, Clerk, Vercel Password Protection
на платном тарифе), чем наращивать этот код.

## Запуск

```bash
npm install
npm run check          # синтаксис всех файлов
npm run hash-password  # сгенерировать логин/пароль/секрет
npm run verify     # проверка источников (нужен доступ к сайтам)
npm run dev        # vercel dev
```

## Перед первым деплоем

Прогони `npm run verify`. В `lib/sources.js` часть RSS-адресов помечена `/* ? */` —
это предположения. Скрипт покажет, какие фиды живы, а где регулярка `articleUrl`
не ловит ссылки, и предложит замену по фактической структуре сайта.

Источники без рабочего RSS обходятся по HTML через `listUrls` — это медленнее,
но работает. Пустой `feedUrls: []` означает «только HTML».

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `AUTH_USERNAME` | — | логин, обязателен |
| `AUTH_PASSWORD_HASH` | — | хеш пароля, обязателен |
| `AUTH_SECRET` | — | подпись сессий, обязателен |
| `AUTH_SESSION_TTL` | 1209600 | срок сессии в секундах |
| `ANTHROPIC_API_KEY` | — | нужен для сводки дня (`/api/claude`) |
| `MAX_ITEM_AGE_HOURS` | 24 | старше — не показываем |
| `SOURCE_LIMIT` | 25 | сколько источников опрашивать за раз |
| `SOURCE_CONCURRENCY` | 5 | параллельных источников |
| `FETCH_TIMEOUT_MS` | 10000 | таймаут запроса |
| `RU_DEFAULT_TZ` | MSK | пояс для времени без указания зоны |
| `USE_FEEDS` | true | использовать RSS там, где он есть |
| `INCLUDE_UNDATED_ITEMS` | false | пускать материалы без даты |

Источников 34, а `SOURCE_LIMIT` по умолчанию 25 — подними до 34, если нужен
полный охват, но следи за таймаутом функции Vercel.

## Что отличается от английской версии

- **Даты.** Добавлен разбор русских форматов: «23 августа 2026, 14:30»,
  «23 августа, 14:30» (год подставляется с откатом на прошлый), «Вчера, 21:15»,
  «Сегодня в 07:40», «12 минут назад», «17 сент. 2025, 11:00».
- **Плашки иноагентов.** Снимаются из заголовков — редакции обязаны их вставлять,
  в ленте они только мешают.
- **Дедупликация.** Заголовки нормализуются с учётом ё/е, кавычек-ёлочек и тире.
  Схлопывание идёт только внутри одного источника: одна новость у «Медузы» и
  «Медиазоны» — два разных материала.
- **Поиск.** Тоже сворачивает ё в е, чтобы «ёлка» находилась по «елка».
- **Убран тумблер EN→RU** — переводить нечего. На его месте фильтр по темам.

## Оговорка про доступ

Часть доменов блокируется в РФ и отдаёт капчу Cloudflare. Serverless-функции
Vercel ходят из дата-центров США/ЕС, так что для прода это обычно не проблема,
но `npm run verify` с российского IP покажет ложные `ERR`.
