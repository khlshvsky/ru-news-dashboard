# ru-news-dashboard

Лента заголовков независимых и эмигрантских русскоязычных СМИ.
Форк `eu-news-dashboard`: та же архитектура (статика + serverless-функции Vercel),
переписанные источники и парсинг под кириллицу.

## Структура

```
index.html          вёрстка
app.js              фронтенд: фильтры, рендер ленты
styles.css          стили (винная палитра)
middleware.js       Edge Middleware: проверка сессии на КАЖДОМ запросе
login.html          страница входа
lib/auth.js         PBKDF2, подпись сессий, куки
lib/users.js        хранилище пользователей (Redis или AUTH_USERS)
api/login.js        POST — проверка пары логин/пароль
api/logout.js       POST — сброс сессии
api/me.js           GET — кто вошёл (для шапки)
api/admin.js        GET/POST — управление пользователями
admin.html          панель администратора
setup.html          первичная настройка (одноразовая)
api/setup.js        создание первого администратора
api/news.js         сбор новостей + кеш в памяти (5 мин)
api/health.js       health check
lib/sources.js      37 источников: URL, регулярки, RSS, политики дат
lib/fetch-news.js   парсер: RSS + HTML, извлечение дат, дедупликация
lib/telegram.js     публикация новых материалов в Telegram + дедупликация
api/telegram-publish.js  защищённый endpoint публикации
tools/verify-sources.mjs   проверка живости источников
tools/manage-users.mjs     заведение и удаление пользователей
```

## Аутентификация

Дашборд закрыт полностью: middleware проверяет сессию до того, как отдать
хоть что-нибудь, включая `/api/news`. Проверки на стороне фронтенда нет
намеренно — она бесполезна, `/api/news` дёргается напрямую в обход любой
JS-логики в браузере.

Пользователей несколько, заводятся администратором через веб-панель. Пароли хранятся
хешами (PBKDF2-HMAC-SHA256, 210 000 итераций, случайная соль) — восстановить
их нельзя ни из базы, ни из переменных окружения.

### Хранилище

Нужен Redis. Подключается за пару минут: в проекте на Vercel открой вкладку
Storage → Marketplace → Upstash → Redis, создай базу и привяжи к проекту.
Переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` пропишутся сами.
Есть бесплатный тариф; в базу ходит только вход и админка, так что лимитов
хватит с запасом.

Без Redis код тоже работает — через переменную `AUTH_USERS` и CLI, — но
админка в этом режиме отдаёт 501: в переменную окружения нельзя писать
во время работы приложения.

Важно: **middleware в базу не ходит**. Кука подписана HMAC и проверяется
локально, поэтому хранилище не влияет на скорость обычных запросов.

### Первый администратор

Без терминала. Открой задеплоенный сайт — если пользователей ещё нет,
тебя перебросит на `/setup.html`.

Страница сама сгенерирует `AUTH_SECRET` и `AUTH_SETUP_TOKEN` (в браузере,
локально), покажет их для копирования в Vercel и проверит, всё ли на месте:
подключён ли Redis, заданы ли переменные, пуста ли база. Дальше вводишь
логин, пароль и код настройки — администратор создан.

`/setup.html` работает ровно один раз: как только в базе появился первый
пользователь, эндпоинт отвечает 410 навсегда, даже с правильным кодом.
Код настройки нужен на случай, если кто-то откроет свежий деплой раньше тебя.

Терминал остаётся запасным путём — см. раздел про CLI ниже.

### Админка

Страница `/admin.html`:

- добавить пользователя: логин, пароль, необязательная заметка;
- кнопка «Сгенерировать» делает случайный пароль из 20 символов без
  путающихся `0/O` и `1/l/I` — скопировать и передать человеку;
- сменить пароль, отключить, включить, удалить;
- выдать или забрать права администратора.

Пароль виден в открытую только в момент создания — потом нигде: в базе
лежит хеш, и наружу API его не отдаёт вообще.

Панель не даст выстрелить себе в ногу: нельзя заблокировать, удалить или
разжаловать самого себя, и нельзя убрать последнего администратора.

### CLI (необязательно)

Нужен только если удобнее из терминала или если потерян доступ к панели.
Требует Node 20+ и файл `.env.local` с теми же переменными.

| Команда | Зачем |
|---|---|
| `node tools/manage-users.mjs add <логин> --admin` | администратор из терминала |
| `node tools/manage-users.mjs promote <логин>` | вернуть доступ к панели, если админов не осталось |
| `node tools/manage-users.mjs list` | посмотреть базу, не заходя на сайт |
| `node tools/manage-users.mjs secret` | новый `AUTH_SECRET` |

### Отзыв доступа: важный нюанс

Сессионная кука самодостаточна — она подписана HMAC и не сверяется с базой.
Это даёт скорость, но значит вот что:

- `disable` и `remove` закрывают **вход** немедленно;
- уже открытая сессия живёт до истечения срока (по умолчанию 14 дней).

Три способа оборвать её раньше:

1. `AUTH_STRICT_SESSION=true` — middleware сверяется с базой на каждом запросе.
   Отзыв мгновенный, платишь задержкой на каждый запрос. Работает только с Redis.
2. Сменить `AUTH_SECRET` — разлогинит **всех** разом.
3. Уменьшить `AUTH_SESSION_TTL`.

Для личного дашборда обычно хватает пункта 2.

### Что здесь слабое

Троттлинг попыток входа (10 за 15 минут) живёт в памяти инстанса. Vercel
поднимает инстансы независимо, так что перебор через них размазывается.
Если нужен настоящий лимит — перенеси счётчик из `api/login.js` в тот же Redis.

Второго фактора нет, сброса пароля по почте нет — пароль меняется только
через CLI. Если дашборд перестанет быть личным, проще подключить готовый
провайдер (Auth0, Clerk), чем наращивать этот код.

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `AUTH_SECRET` | — | подпись сессий, обязателен |
| `AUTH_SETUP_TOKEN` | — | код для `/setup.html`, нужен только при первом запуске |
| `KV_REST_API_URL` | — | Upstash Redis, обязателен для админки |
| `KV_REST_API_TOKEN` | — | токен к нему |
| `AUTH_USERS` | — | запасной режим без Redis, админка недоступна |
| `AUTH_SESSION_TTL` | 1209600 | срок сессии в секундах |
| `AUTH_STRICT_SESSION` | false | сверять сессию с базой на каждом запросе |
| `MAX_ITEM_AGE_HOURS` | 24 | старше — не показываем |
| `SOURCE_LIMIT` | 25 | сколько источников опрашивать за раз |
| `SOURCE_CONCURRENCY` | 5 | параллельных источников |
| `FETCH_TIMEOUT_MS` | 10000 | таймаут запроса |
| `RU_DEFAULT_TZ` | MSK | пояс для времени без указания зоны |
| `USE_FEEDS` | true | использовать RSS там, где он есть |
| `INCLUDE_UNDATED_ITEMS` | false | пускать материалы без даты |
| `TELEGRAM_BOT_TOKEN` | — | токен бота от BotFather |
| `TELEGRAM_CHANNEL_ID` | — | канал в формате `@channel` или числовой ID |
| `TELEGRAM_PUBLISH_SECRET` | — | секрет вызова `/api/telegram-publish`, минимум 16 символов |
| `TELEGRAM_SOURCE_IDS` | — | необязательный список sourceId через запятую; пусто = все источники |
| `TELEGRAM_MAX_PER_RUN` | 5 | максимум сообщений за один запуск, от 1 до 20 |
| `TELEGRAM_BOOTSTRAP_SEND` | false | отправить текущую ленту при первом запуске; иначе только запомнить её |

Источников 37, а `SOURCE_LIMIT` по умолчанию 25 — подними до 37, если нужен
полный охват, но следи за таймаутом функции Vercel.

## Telegram-канал

Бот публикует сообщение в формате `Заголовок — Источник`. Название источника
является ссылкой на оригинальную новость; превью ссылки отключено. Отправленные
URL хранятся 14 дней в том же Redis, который используется для пользователей.

1. Создай бота через `@BotFather` и добавь его администратором канала с правом
   публикации сообщений.
2. Добавь в Vercel переменные `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID` и
   `TELEGRAM_PUBLISH_SECRET`. Последний должен быть случайной строкой длиной
   не меньше 16 символов.
3. В GitHub → Settings → Secrets and variables → Actions добавь:
   `DASHBOARD_URL` (например, `https://ru-news-dashboard.vercel.app`) и
   `TELEGRAM_PUBLISH_SECRET` с тем же значением, что в Vercel.
4. После деплоя открой Actions → Publish Telegram news → Run workflow.
   Первый запуск по умолчанию только запоминает текущие новости. Все новые
   материалы после него будут публиковаться раз в пять минут.

Если используется Vercel Pro, GitHub Actions можно заменить встроенным Vercel
Cron. Endpoint принимает стандартный `CRON_SECRET` тем же Bearer-заголовком.

## Что отличается от английской версии

- **Даты.** Добавлен разбор русских форматов: «23 августа 2026, 14:30»,
  «23 августа, 14:30» (год подставляется с откатом на прошлый), «Вчера, 21:15»,
  «Сегодня в 07:40», «12 минут назад», «17 сент. 2025, 11:00».
- **Плашки иноагентов.** Снимаются из заголовков — редакции обязаны их вставлять,
  в ленте они только мешают.
- **Дедупликация.** Заголовки нормализуются с учётом ё/е, кавычек-ёлочек и тире.
  Схлопывание идёт только внутри одного источника: одна новость у «Медузы» и
  «Медиазоны» — два разных материала.
- **Поиск.** Тоже сворачивает ё в е, чтобы «ёлка» находилась по «елка».
- **Убран тумблер EN→RU** — переводить нечего. На его месте фильтр по темам.
- **Убрана AI-сводка** — лента говорит сама за себя.

## Оговорка про доступ

Часть доменов блокируется в РФ и отдаёт капчу Cloudflare. Serverless-функции
Vercel ходят из дата-центров США/ЕС, так что для прода это обычно не проблема,
но `npm run verify` с российского IP покажет ложные `ERR`.
